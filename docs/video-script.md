# Solution Video Script (5:00 max, the only hard time limit in the submission)

Required structure, per the competition rules: "Begin with the problem and the simple baseline, then walk through one realistic execution from start to finish. Show the final comparison and briefly explain the changelog. Highlight the change that contributed most, and one experiment you removed."

No beat below is spent narrating the harness (the support code that logs and checks runs, built before kickoff). The scaffolding is not the story. Fill every beat below with the real problem and the real solution once they exist.

| # | Beat | Budget | Content (TODO after kickoff) |
| --- | --- | --- | --- |
| 1 | Problem | 0:45 | State the problem and the intended user's bottleneck (what makes their situation painful today). |
| 2 | Simple baseline | 0:45 | Show the baseline (the simple, first-pass solution) running: what it gets right, and what it gets wrong. |
| 3 | One realistic execution, start to finish | 1:40 | Run the advanced solution (the improved version built on top of the baseline) on a real input, end to end. No cuts that hide a failure. |
| 4 | Final comparison | 0:40 | `results/comparison.md` or equivalent: baseline vs advanced, with the actual numbers, not just a claim. |
| 5 | Changelog walk | 0:25 | The 2 to 3 iterations (a change plus the evidence that drove it) that mattered most, briefly. |
| 6 | Biggest contributor plus one removed experiment | 0:30 | Name the single change that had the most impact, and one thing that was tried, cut, and why. |

Total: 4:45, leaving a 0:15 buffer under the 5:00 ceiling. If running long, cut beat 5 first. Never cut beat 3.
