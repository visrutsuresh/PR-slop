PR-slop · how it works

Four helpers, one page, nothing touched.

What the thing we built actually does, in order, with nothing left out.

The job

A volunteer has a pile. Which ones matter?

It never touches anything. It cannot accept, reject, close or comment. It writes a page. That is on purpose, not a missing feature: closing someone's work affects a real person.

The machine

One submission goes in. Four helpers look at it in turn.

1 · Investigator

Has somebody already complained about this?

The project has 403 old complaints written down. Far too many to hand over at once. So this helper decides what words to search for, reads what comes back, and judges whether any of it is really the same problem.

It writes its own search. From a title with none of these words it asked for snippet tab stop limit 10 nested placeholders, because a person complaining uses different words from a developer fixing. It chose to go back and search again 6 times out of 15.

2 · Fact checker

Does the code do what the note says it does?

It reads the project's actual source, not the description. We fetch the file and hand it over, so the helper still cannot go rummaging for answers.

It looks at the source every time. On 5 of 15 it answered "cannot tell" instead of guessing.

3 · Decider

Which pile?

It sees what the other two found and picks. It is not allowed to shrug: a sorting tool that refuses to sort leaves the volunteer reading everything anyway.

4 · Checker

Is any of this made up?

Every complaint number it mentions gets looked up. If it does not exist, the answer goes back to be redone. Honest count: this fired once in fifteen. We keep it because it is free and the simple version really did invent two references out of three.

The obvious question

Why not just ask a computer once?

We tried. It scored 33.3%. With three piles, guessing scores 33.3%.

It cannot look anything up.

Asked which old complaint a submission fixes, it named three. Two did not exist. It was not lying on purpose. It had no way to check, and it had been asked for an answer.

Ours names five and all five are real.

And on four submissions it named nothing at all, because it had nothing solid. Saying nothing is allowed. Inventing is not.

What you get

One page. Type ./run.sh triage.

PULL REQUEST TRIAGE microsoft/vscode ============================================================== 10 open, 5 recently closed. Nothing has been touched. This is a reading list, not an action. READ THESE FIRST (4) Close something already reported. 19 files, 660 lines added. #331442 Enforce custom agent subagent allowlists fixes reported #331002 | code matches its description | has tests | 166 lines, 2 files https://github.com/microsoft/vscode/pull/331442

Every fact on that line was checked. The complaint number is real. "Code matches its description" came from reading the source. The size is counted.

The part we are proudest of

It also says: “you may have thrown away something good.”

Here is a problem we could not argue away. We taught it by showing it what volunteers did. So if a volunteer misses something valuable and bins it, and our tool correctly says the work is good, we mark our own tool wrong.

One submission proved it. Out of six attempts at building this, not one ever got #308696 right. Real code. Fixes a genuinely reported complaint. We checked it against the actual source. Binned anyway. Every version said “this is good work” and we scored every version as wrong.

So we added a second output that judges the work instead of the decision. Only things that are true or false: is the complaint real, does the code match, are there tests, is it substantial.

SECOND OPINION ============================================================== Closed without merging, but the evidence says otherwise. Not an accusation. Worth thirty seconds each. #308696 Close non-dirty editors when cancelling Close All fixes a genuinely reported problem #305306 code confirmed to match its description 44 lines added -> closed without merging. Worth a second look.

Our worst failure became the headline feature. The one case nothing could ever get right is now the top line of the most useful thing the tool produces.

Why you can believe the numbers

We caught ourselves cheating, before anyone else could.

It could open the answer sheet.

We asked it for the answer to one case. It found the file and read it out. Every score after that would have been worthless.

Now it runs in an empty room with the door locked. No file reading, no searching, no internet. A test has to prove it is blind before anything else is allowed to run. You can watch that test: ./run.sh probe.

Nothing to install, nothing to pay.

Every answer it ever gave is saved in the project. The commands add the scores back up from those files. Same numbers, any machine, no account.

Check the workings.

./run.sh versions rebuilds our whole results table in front of you, including the two versions we made worse.

And what it still gets wrong. The decider sometimes overrules the investigator when the investigator was right. Twice out of fifteen. We tried to fix it and made things dramatically worse, so it ships with the flaw written down rather than hidden.

In one line

It reads the pile so a volunteer does not have to, and it shows its working.

Four helpers, one page, every claim checked, nothing touched, and an honest note when it thinks a human got one wrong.
