# Agent trajectories

This indexes the step-by-step record of what the shipped agent (`src/agent_v4.py`) actually did on every case: agent instructions, tool responses, feedback, retries, and the one human checkpoint. It does not duplicate `traces/INDEX.md`, which lists every trace file and is regenerated by `src/harness/trace.py`; this file explains how to read one.

## The four roles in the loop

- **investigator** — chooses what to search for among the project's recorded problems, then judges whether the results actually match.
- **claim_checker** — reads the real source file the investigator pointed at and judges, in isolation, whether the claim holds against the actual code.
- **adjudicator** — decides the pile (act now / worth reviewing / not merged) from what the investigator found and the claim checker judged.
- **verifier** — checks every citation the adjudicator used against the real repository. A failed citation is sent back to the adjudicator to redo, in the same run, before the case is scored.

## Read one, walked through

`traces/agent-1788116123731.md` (pull request 333295) is the exemplar: it is the only agent trace in this evaluation set where the verifier actually sends work back.

- Steps 1-2: investigator searches, then judges the results a match.
- Step 3: claim_checker reads the real source and finds the diff does not match what is currently in the repository.
- Step 4: adjudicator's first attempt cites `#330142`.
- Step 5: verifier fails that citation (`#330142 is not a real recorded problem in this project`) and sends it back — this is the retry.
- Step 6: adjudicator's second attempt drops the bad citation and re-decides the pile.
- Step 7: verifier checks the new citations and passes.
- Step 8: human checkpoint — the page goes to the maintainer; nothing here posts, comments, closes or merges anything.
